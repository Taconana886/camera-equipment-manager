# 项目对话记录（完整整理）

> 本文档整理了「记者团器材管理」小程序从需求到上线的完整过程，方便后续回顾和继续开发。

## 一、初始需求（项目起点）

用户想做一个摄影器材管理小程序，需求如下：

1. 管理员可以添加、删除器材
2. 借用器材需登录小程序、填写姓名记录在案
3. 借走的器材标注「已借出」，没借走的标注「在器材室」
4. 用户通过个人微信登录
5. 可以添加管理员协助管理

**技术选型**：微信云开发（云函数 + 云数据库 + 云存储），无需自建服务器。

**器材字段**：名称+编号、品牌型号、图片、备注。

## 二、项目搭建

### 目录结构

```
camera-equipment-manager/
├── miniprogram/          # 小程序前端
│   ├── pages/
│   │   ├── login/        # 登录页
│   │   ├── index/        # 首页（器材列表）
│   │   ├── equipment/    # 器材详情
│   │   ├── admin/        # 管理后台
│   │   └── records/      # 借用记录
│   └── utils/            # 工具函数
├── cloudfunctions/       # 云函数
│   ├── login/            # 登录注册
│   ├── equipment/        # 器材增删改查
│   ├── borrow/           # 借用/归还
│   ├── admin/            # 用户管理
│   └── init/             # 初始化集合
├── web/                  # 网页版（备用）
```

### 数据库集合

- `users`：用户（姓名、是否管理员、头像、密码、token）
- `equipment`：器材（名称、部门、分类、编号、品牌、图片、备注、状态、借用人、借用原因）
- `borrow_records`：借用记录

## 四、审核问题与整改

第一次提交审核被拒，原因：**「一进入首页就要求授权登录」**。

整改方案：**先浏览后登录**
- 未登录也能浏览器材列表
- 只有点「借用/归还」时才要求登录
- 登录成功后返回原页面

整改后重新提交，**审核通过，正式上线**。

## 五、功能演进（按时间顺序）

### 1. 器材分类
增加分类：机身、镜头、内存卡、电池、闪光灯、读卡器。

### 2. 用户头像自定义
- 用户可上传头像、修改姓名
- 首页顶部点击头像编辑资料

### 3. 归还需拍照
归还器材时需拍一张照片作为归还凭证，记录在借用记录里。

### 4. 借用记录页面
- 普通成员看自己的记录
- 管理员看全部记录

### 5. 借用申请原因
借用器材时必填借用原因。

### 6. 踢出用户
管理员可移除用户，被移除者自动登出。

### 7. 管理员查看成员头像
用户管理列表显示成员头像，可点击放大。

### 8. 部门功能（最新）
器材增加「部门」维度：
- **记者团**：机身、镜头、内存卡、电池、闪光灯、读卡器
- **电视台**：机身、镜头、稳定器、内存卡、灯具、电池、图传、无人机、麦克风、脚架、读卡器、硬盘、其他

首页支持按部门 + 分类两级筛选。

### 9. 分享功能
首页和详情页支持微信分享。

## 六、网页版探索（未上线）

用户曾想做一个网页版（用 NFC 贴片触发），避免小程序审核和人数限制。

探索过程：
1. 尝试复用云开发做网页版（改造云函数为双认证：openid + token）
2. 尝试本地笔记本存储（D盘），因「笔记本会关机」放弃
3. 尝试内网穿透，因「免费版域名随机、付费版要钱」放弃

**最终结论**：小程序重新审核通过、正式上线，无人数限制，是最优方案。网页版代码保留在 `web/` 目录备用。

## 九、技术要点总结

- 前端：微信小程序（WXML/WXSS/JS）
- 后端：微信云开发（云函数、云数据库、云存储）
- 身份认证：微信 OpenID（小程序）+ token（网页备用）
- 权限：首个注册用户是管理员，可添加/移除管理员
- 数据：全部云端存储，多端同步
